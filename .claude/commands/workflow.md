Sigue esta estructura para la implementación de una tarea asignada:

1. Crea una issue en Github (vía `el mcp de github`).
2. A raíz de esa issue crea una rama partiendo de **main/master**.
3. Cambiate a esa rama para trabajar.
4. Emplea la skill `grill-me` para discutir con el usuario sobre la _feature_.
5. Usa la skill `to-prd` para documentar lo que se haya acordado.
6. Puedes usar la skill `to-issues` para dividir tareas.
7. Implementa la funcionalidad usando la skill `tdd`. Si no hay codebase ni dependencias de testing unitario, instalalo eligiendo lo más óptimo.
8. Usa la skill `improve-codebase-architecture` para revisar y mejorar el codigo creado.
9. Revisa el codigo creado también usando las siguientes skills: `next-best-practices`, `next-cache-components`, `next-upgrade`, `vercel-composition-patterns`, `vercel-react-best-practices`, `vercel-react-view-transitions` y `typescript-advanced-types`.
9. Usa la skill `verification-before-complete` para asegurarte de que se ha verificado todo. Si hay errores usa la skill `diagnose`.
10. Informa al usuario para que pruebe la implementación.
11. Si el usuario te da el "OK", haz commit y push cerrando la `issue` y crea una Pull Request en **Github**. Si no ha dado el ok, seguimos iterando.
